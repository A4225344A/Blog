This article explains the content model behind A Full-Stack Engineer’s Blog. The first three articles produce a deployable site. This one examines what changes when articles need translations, ordered series and topic discovery.

The repository uses Astro 5, TypeScript, Markdown and Pagefind. Pages and search indexes are generated during the build; GitHub Pages serves the files. Paths below refer to this repository.

## Run the repository locally

Use the series setup: Node.js 24.x and pnpm 10.32.1. Install Node.js and Git as described in article two, then run `npm.cmd install --global pnpm@10.32.1` in PowerShell. The repository accepts Node 22.12 or later; these instructions consistently use 24.x.

```powershell
git clone https://github.com/A4225344A/Blog.git
cd Blog
pnpm.cmd install --frozen-lockfile
pnpm.cmd run content:validate
pnpm.cmd run test
pnpm.cmd run check
pnpm.cmd run build
pnpm.cmd run test:build
pnpm.cmd run preview
```

Frozen installation uses the committed dependency resolution. Check runs Astro and TypeScript diagnostics. Build generates `dist` and the Pagefind index, then test:build inspects links and metadata in the resulting files.

Use `pnpm.cmd run dev` while editing. Search needs an index generated by build, so stop dev, build and preview when testing search. Preview serves the previous build; changing a source file does not update that output until another build.

## Store an article once and build several entry points

```text
src/content/
  articles/zh-tw/     Traditional Chinese articles
  articles/en/        English articles
  topics/            Browsing categories
  skills/            Capabilities and prerequisites
  learning-paths/    Ordered article series
  projects/          Project information
```

Articles use Markdown with frontmatter: metadata between the opening `---` lines. The other four entities use JSON. Their schemas, or accepted fields and types, live in `src/content/schemas.ts`.

A topic page and a series can both link to an article without duplicating its body. Updating the source changes the one canonical article they point to.

### Identity, translations and URLs

| Field | Purpose |
| --- | --- |
| id | Stable identity used by series and project references |
| translationKey | Groups equivalent language versions |
| slug | The presentation part of the public URL |

The first three articles once used beginner-* URLs. Their rewritten versions now have descriptive URLs. Old entry points explain the changed audience and link to the revised content. The article IDs remain stable so moving a URL does not rewrite its relationships.

### Who owns reading order

A LearningPath represents a series; its sections[].articleIds owns reading order. The four Astro articles now form one series: selection, project setup, content and deployment, then this architecture walkthrough. Filtering by locale and publication status preserves that order.

Projects own their related articles. Articles own their topic, skill and recommended-reading references. `src/utils/graph.ts` computes reverse indexes for questions such as which series includes this article, rather than storing a second hand-maintained list.

AI SRE Platform is a separate lab with no related articles yet. The Astro series describes the blog, so it does not belong to that project.

## Check source data before rendering

Astro loads content by ID. Duplicate IDs can overwrite one another before a later check sees them. `src/utils/content-source.ts` reads the original files and retains source paths before validating them.

Duplicate IDs, missing references, invalid metadata and forbidden article fields stop the build with a nonzero exit. For example, Article cannot declare order because the series already owns it. Diagnostics identify the source so the error can be corrected before deployment.

Other conditions are warnings. Articles without project membership produce W_ARTICLE_NO_PROJECT but remain publishable; that describes the current Astro articles. Advanced checks such as skill dependency cycles are not implemented.

## Language routes and search metadata

Traditional Chinese uses /zh-tw/ and English uses /en/. General articles live under /blog/; troubleshooting and case studies use /cases/. Only published content enters public article lists, RSS and search.

Language switching uses translationKey to find the corresponding published article, then uses that version’s own URL. Without a translation, it returns to the target-language home.

Canonical identifies the article’s primary URL. Hreflang lists existing translations. The language chooser uses x-default for readers without a specified language. The layout generates these markers rather than asking authors to repeat them in every article.

Shared topics and projects have one entity each. Their display translations live in src/i18n/content.ts and do not create extra graph entities.

## Search and reading without a backend

Pagefind reads generated article and detail-page HTML to build a local index. It excludes home pages and navigation so menus do not dominate results. The search page loads files from the deployment directory without a remote search service.

Traditional Chinese queries work, but Pagefind does not stem zh-tw words: it does not automatically match different word forms. That limitation does not mean search is unavailable.

Article bodies and tables of contents are static HTML. A small script remembers light, dark or system appearance. The site does not require a React application to render text, and keyboard readers can skip navigation.

## GitHub Pages deployment paths

https://name.github.io is the origin, or scheme and host. /Blog/ is the base deployment path. Images, article links and search results must all use that base.

These variables affect only the current PowerShell session:

```powershell
$env:SITE_URL = 'https://YOUR_USERNAME.github.io'
$env:SITE_BASE = '/Blog/'
pnpm.cmd run build
pnpm.cmd run test:build
pnpm.cmd run preview
```

Stop preview, then clear them before normal local development:

```powershell
Remove-Item Env:SITE_URL, Env:SITE_BASE -ErrorAction SilentlyContinue
pnpm.cmd run dev
```

Sitemap lists public URLs and RSS exposes article updates per language. /Blog/robots.txt cannot set origin-wide crawler policy; that belongs in the owner site’s https://name.github.io/robots.txt.

## Publish the output that was checked

The repository workflow runs installation, content validation, tests and builds on PRs and main pushes. PRs do not deploy. A successful main run preserves its output. The deployment job waits for github-pages approval only if Required reviewers are configured, then verifies that main still has the same commit SHA, the Git revision identifier.

Deployment does not rebuild because I want the published files to be the files already inspected. Only that job receives Pages write and short-lived identity permissions. Required reviewers and branch restrictions must be configured in GitHub; an environment name in YAML does not enable them.

Optional GA4 follows a separate boundary. Browser tests use a synthetic Measurement ID. Only the final production artifact receives the real ID, and it is checked statically without running it in a test browser. GA4 does not define content relationships or provide a public view counter on this site.

The small blog from the preceding articles is enough for publishing a few pages. This repository adds a content model when those pages need shared categories, ordered series and translations. For your own blog, consider which relationships you need to maintain and which checks would catch a broken link before readers reach it.
