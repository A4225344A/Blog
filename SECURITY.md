# Security policy

Security fixes target the current `main` branch. Older commits and tutorial
snapshots are not maintained release branches.

Do not post credentials, personal data or exploit details in a public issue.
Use [GitHub's private vulnerability reporting](https://github.com/A4225344A/Blog/security/advisories/new)
when the repository's **Report a vulnerability** option is available. This
requires the maintainer to enable private vulnerability reporting in Settings.
If unavailable, request a private reporting channel without including exploit
details or secrets in that request.

Include the affected URL or commit, reproduction steps and expected impact.
Do not test against other visitors or submit real secrets as proof.

The deployed site is static. Build-time dependencies, repository permissions
and approved third-party analytics still require review. See
[the security baseline](docs/security.md) for controls and limitations.
